### Breaking

- **`search`, `suggest`, `index-document!` and `reindex!` on a tenant-scoped search index refuse a call naming no tenant**
  (BOU-1114): a forgotten filter read every organisation. Pass `:tenant-id`, or `:all-tenants? true` to read all.

### Added

- **`ISearchTenantRemoval/remove-tenant-document!` removes a search document only within its tenant** (BOU-1114).
  `reindex!` takes `[entity-id field-values opts]` triples, so a tenant-scoped index keeps its filter values.

## Upgrading

### Name the tenant in every call on a tenant-scoped search index (BOU-1114)

An index whose `:filters` include `:tenant-id`, and that is not `:global? true`, now throws a `:validation-error`
for a call without a tenant. Give `search` and `suggest` `:filters {:tenant-id t}` (one tenant or a set), or
`:all-tenants? true` where a platform admin reads every tenant. Give `index-document!` `:filter-values
{:tenant-id t}`, and `reindex!` triples `[entity-id field-values {:filter-values {:tenant-id t}}]`. A custom
search store needs `ISearchStoreTenantDeletion` for `remove-tenant-document!`.
