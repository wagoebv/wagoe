= jobs
:description: Background job processing with priority queues, retries, and multi-tenant support.

Background job processing with priority queues, scheduled execution,
automatic retries with exponential backoff, and multi-tenant support.

== Key namespaces

[cols="1,3",options="header"]
|===
| Namespace | Purpose

| `wagoe.jobs.core.job`
| Pure functions: job creation, state transitions, retry logic

| `wagoe.jobs.ports`
| Protocols: `IJobQueue`, `IJobStore`, `IJobStats`, `IJobWorker`, `IJobRegistry`, `IIdempotencyStore`, `IRecurringState`

| `wagoe.jobs.core.cron`
| Pure cron parsing and next-run calculation

| `wagoe.jobs.shell.recurring`
| Recurring-job ticker and `enqueue-once!`

| `wagoe.jobs.schema`
| Malli schemas: job states, priorities, retry config

| `wagoe.jobs.shell.adapters.in-memory`
| In-memory adapter (atoms, for dev/test)

| `wagoe.jobs.shell.adapters.redis`
| Redis adapter (sorted sets, lists, hashes)

| `wagoe.jobs.shell.worker`
| Worker implementation: polling, processing, pool management

| `wagoe.jobs.shell.tenant-context`
| Multi-tenant job execution with schema switching
|===

== Handler signature

[source,clojure]
----
;; Handlers receive args map, return result map
(defn send-email-handler [args]
  {:success? true
   :result {:sent-to (:email args)}})

;; Failing handler
(defn failing-handler [args]
  {:success? false
   :error {:message "Processing failed" :type :processing-error}})
----

== Enqueueing jobs

[source,clojure]
----
(require '[wagoe.jobs.core.job :as job]
         '[wagoe.jobs.ports :as ports])

(let [new-job (job/create-job {:job-type    :send-email
                                :args        {:to "user@example.com"}
                                :priority    :high
                                :max-retries 3}
                               (random-uuid))]
  (ports/enqueue-job! job-queue :default new-job))
----

Priority levels: `:critical`, `:high`, `:default`, `:low`, `:bulk`.

(require '[wagoe.jobs.shell.worker :as worker])

== Recurring jobs

Declare cron schedules on `:wagoe/jobs`. Each tick enqueues a job of that
type; the handler is the one registered for it.

[source,clojure]
----
:wagoe/jobs {:provider  :db
             :recurring {:nightly-report {:cron "0 2 * * *"
                                          :zone "Europe/Amsterdam"
                                          :args {:kind :sales}}}
             :scheduler {:tick-ms 5000 :lease-ms 30000 :zone "UTC"}}
----

Or at runtime, on the `:wagoe/job-scheduler` component:

[source,clojure]
----
(require '[wagoe.jobs.shell.recurring :as recurring])

(recurring/schedule-recurring! scheduler :nightly-report "0 2 * * *"
                               {:zone "Europe/Amsterdam" :queue :reports})
----

Expressions have five fields (minute, hour, day of month, month, day of
week) with `*`, lists, ranges, steps and names (`MON`, `JAN`), plus
`@hourly`, `@daily`, `@weekly`, `@monthly` and `@yearly`. A malformed
expression, an unknown zone, or one that never fires fails the boot.

How it behaves:

* *One replica enqueues.* Every replica runs a ticker; the one holding a
  lease enqueues (a database row timed by the database clock under `:db`,
  `SET NX PX` under `:redis`). Each tick is also claimed as an idempotency key,
  job type plus scheduled instant, so two tickers overlapping after a lease
  handover still enqueue it once.
* *Zones are wall-clock.* The zone defaults to UTC. A time skipped by a DST
  jump runs at the shifted instant; a time that occurs twice runs once.
* *Missed ticks run at most once.* After downtime a schedule runs its latest
  missed tick once and skips the earlier ones. A new schedule does not run for
  ticks before it was registered.
* *A tick is enqueued at most once.* A process that dies between claiming a
  tick and enqueueing it loses that tick.
* `:provider :memory` keeps all of this in one process.

== Idempotency keys

`enqueue-once!` enqueues unless the job type and key were claimed before, so a
retried request does not queue the same work twice. It returns the job id, or
nil for a duplicate. Claims last a week unless `:ttl-ms` says otherwise.

[source,clojure]
----
(recurring/enqueue-once! job-queue idempotency-store :default receipt-job
                         (str "receipt/" order-id))
----

The store behind it, `:wagoe/idempotency-store`, implements
`wagoe.jobs.ports/IIdempotencyStore` (`claim-key!`, `release-key!`) on the
jobs provider's backend, for any module to use.

== Retry behaviour

Failed jobs retry with exponential backoff:

* Attempt 1: immediate
* Attempt 2: 30 seconds
* Attempt 3: 5 minutes
* Attempt 4: 1 hour
* After `max-retries`: moved to dead letter queue

== Redis counters

Stats are stored as Redis keys: `stats:global:*` and `+stats:queue:{name}:*+`.
