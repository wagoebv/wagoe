= ai
:description: Framework-aware AI tooling including NL scaffolding, error explainer, test generator, SQL copilot, and docs wizard.

Framework-aware AI tooling for Wagoe applications. Unlike a generic assistant, it knows Wagoe's conventions: FC/IS, ports, kebab↔snake naming, Malli schemas, and HoneySQL syntax.

== Features

1. *NL Scaffolding* - parse a natural language description into a scaffolding spec
2. *Error Explainer* (experimental) - explain a stack trace with Wagoe-specific context
3. *Test Generator* (experimental) - generate a complete test namespace for a source file
4. *SQL Copilot* (experimental) - translate a description into HoneySQL format
5. *Documentation Wizard* - generate AGENTS.md, OpenAPI YAML, or README

WARNING: The error explainer, test generator and SQL copilot are experimental for 1.0: their answers can be confidently wrong, so review them before use. `bb ai explain` prints the error's own BND code and `Fix:` text before the model's summary.

== CLI commands

[source,bash]
----
# NL scaffolding (interactive confirm)
bb scaffold ai "product module with name, price, stock"

# NL scaffolding (non-interactive)
bb scaffold ai "product module with name, price, stock" --yes

# Explain a stack trace (experimental)
bb ai explain --file stacktrace.txt

# Generate test namespace (experimental)
bb ai gen-tests libs/user/src/wagoe/user/core/validation.clj

# Generate HoneySQL from description (experimental)
bb ai sql "find active users with orders in the last 7 days"

# Generate documentation
bb ai docs --module libs/user --type agents
bb ai docs --module libs/user --type openapi
bb ai docs --module libs/user --type readme
----

== Prerequisites per provider

The config a provider needs is written by `bb setup --ai-provider <name>`;
what the provider needs *outside* the config is this table. The project boots
without any of it — the first AI call is what fails.

[cols="1,3"]
|===
|Provider |Before the first call answers

|`:ollama`
|Install Ollama (https://ollama.com/download), pull the configured model
(`ollama pull qwen2.5-coder:7b` for the default), and keep it running —
the service calls `localhost:11434`. No API key, no data leaves the machine.

|`:anthropic`
|Create a key at https://console.anthropic.com/settings/keys and export
`ANTHROPIC_API_KEY` (or put it in `.env` and load it with
`set -a; source .env; set +a` — plain `source` does not export, so the
JVM would not see it).

|`:openai`
|Create a key at https://platform.openai.com/api-keys and export
`OPENAI_API_KEY`.

|`:replicate`
|Create a token at https://replicate.com/account/api-tokens and export
`REPLICATE_API_TOKEN`.
|===

`bb doctor --ci` names a missing key for the hosted providers. It does not
probe whether Ollama is running.

== Provider strategy

Offline-first by default: uses Ollama (no data leaves the machine).
Falls back to cloud providers if configured:

[source,clojure]
----
;; Offline-first (Ollama, no API key)
:wagoe/ai-service
{:provider :ollama
 :model    "qwen2.5-coder:7b"
 :base-url "http://localhost:11434"}

;; Anthropic
:wagoe/ai-service
{:provider :anthropic
 :model    "claude-haiku-4-5-20251001"
 :api-key  #env ANTHROPIC_API_KEY}

;; Ollama primary + Anthropic fallback
:wagoe/ai-service
{:provider  :ollama
 :model     "qwen2.5-coder:7b"
 :base-url  "http://localhost:11434"
 :fallback  {:provider :anthropic
              :api-key  #env ANTHROPIC_API_KEY}}
----

CLI provider resolution order: `ANTHROPIC_API_KEY` → `OPENAI_API_KEY` → `OLLAMA_URL`.

== Key namespaces

[cols="1,2,3",options="header"]
|===
| Namespace | Layer | Responsibility

| `wagoe.ai.ports`
| shared
| `IAIProvider` protocol: `complete`, `complete-json`, `provider-name`

| `wagoe.ai.core.prompts`
| core
| Pure prompt builders for all 5 features

| `wagoe.ai.core.context`
| core
| Pure context extractors (module names, stack traces, function signatures)

| `wagoe.ai.core.parsing`
| core
| Pure response parsers (JSON, module spec, SQL, test code)

| `wagoe.ai.shell.providers.ollama`
| shell
| Ollama HTTP adapter

| `wagoe.ai.shell.providers.anthropic`
| shell
| Anthropic API adapter

| `wagoe.ai.shell.providers.openai`
| shell
| OpenAI API adapter

| `wagoe.ai.shell.providers.no-op`
| shell
| Test stub

| `wagoe.ai.shell.service`
| shell
| Public API: `scaffold-from-description`, `explain-error`, `generate-tests`, `sql-from-description`, `generate-docs`

| `wagoe.ai.shell.repl`
| shell
| REPL helpers: `explain`, `sql`, `gen-tests`
|===

== REPL usage

[source,clojure]
----
(require '[wagoe.ai.shell.repl :as ai])

;; Bind a service
(ai/set-service! (create-service-from-config))

;; Use helpers
(ai/explain "ClassNotFoundException: wagoe.user.core.user")
(ai/sql "find all users who logged in today")
(ai/gen-tests "libs/user/src/wagoe/user/core/validation.clj")
----
