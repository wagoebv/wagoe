= push
:description: Multi-platform push notifications via FCM and APNs with declarative definitions and reliable delivery.

Multi-platform mobile push notifications. Notifications are declared
with the `defpush` macro and delivered through Firebase Cloud Messaging
(FCM) and the Apple Push Notification service (APNs) behind a unified
service, with job-backed reliable delivery and delivery analytics.

== Key namespaces

[cols="1,3",options="header"]
|===
| Namespace | Purpose

| `wagoe.push.core.notification`
| Pure: locale resolution and template rendering

| `wagoe.push.shell.registry`
| `defpush` macro and the definition registry

| `wagoe.push.core.delivery`
| Pure: delivery planning + error classification (retryable / permanent / token-invalid)

| `wagoe.push.core.device`
| Pure: device-token lifecycle logic (registration, rotation, deactivation)

| `wagoe.push.core.analytics`
| Pure: delivery analytics aggregation

| `wagoe.push.ports`
| Protocols: `IPushService`, `IFCMProvider`, `IAPNsProvider`, `IDeviceTokenStore`, `IPushAnalyticsStore`

| `wagoe.push.shell.service`
| Orchestrator dispatching to platform providers

| `wagoe.push.shell.adapters.fcm`
| FCM provider — async parallel delivery via `sendAsync` + `CompletableFuture`

| `wagoe.push.shell.adapters.apns`
| APNs provider — async parallel delivery via `sendAsync` + `CompletableFuture`

| `wagoe.push.shell.handlers`
| REST endpoints (devices, callback, stats)
|===

== Declaring notifications

The `defpush` macro defines notifications declaratively with i18n locale
maps, deep links, priority, TTL, collapse keys, and retry configuration.

== Device tokens

Device token lifecycle is managed end to end — registration, rotation,
soft-deactivation, and cleanup of stale tokens. Tokens are stored with
multi-tenant support.

== Reliable delivery

`send-push!`, `schedule-push!` and `broadcast!` enqueue `:push/send` and
`:push/broadcast` jobs, so the `:wagoe/jobs` module must be enabled; the
handlers and queue are wired only then. Each device's result is recorded in
`push_send_log`, and a token the provider reports invalid is deactivated.
A failed send to one device is not retried; a job retries only when its
handler throws.

== Analytics

An HMAC-secured callback endpoint accepts client-reported delivery and
open events, recorded in `push_analytics_events`.

== Endpoints

[cols="1,3",options="header"]
|===
| Endpoint | Purpose

| `/api/v1/push/devices` | Register and list the caller's device tokens
| `/api/v1/push/devices/:token` | Unregister one
| `/api/v1/push/callback` | HMAC-secured delivery/open analytics callback (public)
| `/api/v1/push/stats/:notification-id` | Per-notification delivery stats (`:push/read`)
|===

The module mounts these routes itself. Every route but the callback needs a
signed-in user.
