= calendar
:description: Recurring events, RRULE recurrence, iCal export/import, and conflict detection.

Handles recurring events, timezone-aware occurrence expansion, conflict detection,
iCal export/import, and admin UI components for scheduling applications.

== Key namespaces

[cols="1,2,3",options="header"]
|===
| Namespace | Layer | Responsibility

| `wagoe.calendar.schema`
| shared
| Malli schemas: `EventData`, `EventDef`, `OccurrenceResult`, `ConflictResult`

| `wagoe.calendar.ports`
| shared
| `CalendarAdapterProtocol`, implemented by the `:wagoe/calendar` component

| `wagoe.calendar.core.event`
| core
| `duration`, `all-day?`, `within-range?`

| `wagoe.calendar.shell.registry`
| shell

| `wagoe.calendar.core.recurrence`

| `wagoe.calendar.core.ui`

== Defining event types

[source,clojure]
----
(require '[wagoe.calendar.shell.registry :as registry])

(registry/defevent appointment-event
  {:id     :appointment
   :label  "Appointment"
   :schema [:map
            [:patient-id :uuid]
            [:room       :string]]})

(registry/get-event-type :appointment)   ;=> {:id :appointment ...}
(registry/list-event-types)              ;=> [:appointment ...]
----

== Recurring events (RRULE)

[source,clojure]
----
(require '[wagoe.calendar.core.recurrence :as recurrence])

;; Expand weekly recurring event
(recurrence/occurrences event-data start-dt end-dt)

;; Next occurrence from an explicit reference instant
(recurrence/next-occurrence* event-data after-dt)

;; Full expansion with metadata
(recurrence/expand-event event-data range-start range-end)
----

== Conflict detection

[source,clojure]
----
(require '[wagoe.calendar.core.conflict :as conflict])

(conflict/overlaps? event-a event-b)    ;=> true/false
(conflict/find-conflicts events window-start window-end)
;=> ({:event-a ... :event-b ... :overlap-start ... :overlap-end ...})
----

== UI components

[source,clojure]
----
(require '[wagoe.calendar.core.ui :as ui])

(ui/month-view 2026 3 events {:timezone   "Europe/Amsterdam"
                              :event-href #(str "/appointments/" (:id %))
                              :t          t-fn})
(ui/week-view (java.time.LocalDate/of 2026 3 2) events {:t t-fn})
----

* An event's `:href`, or the `:event-href` option, turns its badge into a link.
* Weekday and month labels are `[:t ...]` markers. They resolve only through
  `wagoe.i18n.shell.render`; plain `hiccup2.core/html` prints them as `<t>`
  tags. Pass `:t` (key -> string) to resolve them when the hiccup is built.
* Multi-day events show on every day they cover, clipped to the visible range;
  the week view puts those of 24 hours or more in an all-day row. Mark all-day events
  `:all-day? true`: they show no time and keep their dates in the event's own
  `:timezone`.

== iCal export / import

The `:wagoe/calendar` component implements `CalendarAdapterProtocol`. Take
`(ig/ref :wagoe/calendar)` and call it through the ports:

[source,clojure]
----
(require '[wagoe.calendar.ports :as cal]
         '[wagoe.calendar.core.feed :as feed])

;; Export to iCal string
(cal/export-ical calendar events {})

;; Import from iCal string; :timezone places events without a TZID
(cal/import-ical calendar ical-string {:timezone "Europe/Amsterdam"})

;; Ring response for a feed (subscription URL): content type, filename, caching
(feed/ical-response (cal/export-ical calendar events {}) {:filename "appointments.ics"})
----

An `:all-day? true` event is written as `DTSTART;VALUE=DATE` with an exclusive
`DTEND`, and a `VALUE=DATE` event is read back `:all-day? true`. `event/all-day?`
reads that flag and nothing else.

Import reads a TZID that names an IANA zone, or a Windows one such as
`W. Europe Standard Time`, with the JVM's tz rules, whatever the feed's
VTIMEZONE says, and returns it as `:timezone`. Any other TZID is read with its
VTIMEZONE, and `:timezone` is the option's.

Without Integrant, `wagoe.calendar.shell.service` offers the same calls.
