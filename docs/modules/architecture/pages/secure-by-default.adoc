= Secure by Default
:description: Each security measure Wagoe takes for you: what is on by default, the key that changes it, and the test that fails when it breaks.
:repo: https://github.com/wagoebv/wagoe/blob/main/

This is an inventory, not a claim. Each row says what a generated application
does without configuration, where you change it, and which test holds it. A
row with no test says so.

Tests tagged `:security` also run as their own required job on every code
change; the others run in their library's job.

== What you do yourself

* *TLS.* Wagoe sets HSTS and `Secure` cookies; something in front of it has to
  terminate HTTPS.
* *CSRF and rate limiting.* Keep both on in the profile you deploy; rate limiting there needs an active `:wagoe/cache`.
* *Secrets.* Keep them in your platform's secret store and read them with
  `#secret` or `#env`.
* *Backups, OS and JVM patches, database access.* Outside the framework.

== What we do not claim

Wagoe has had no external audit and no penetration test. It has one
maintainer.
