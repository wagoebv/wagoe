# shop — Developer Reference

Built with the Wagoe Framework. Follows the Functional Core / Imperative Shell (FC/IS) pattern.

---

## Essential Commands

```bash
# REPL (prompt + nREPL on port 7888) — JWT_SECRET is pre-set in .env
source .env
bb repl

# Shorthand via bb tasks
bb repl          # clojure -M:repl --interactive
bb test          # same as clojure -M:test
bb migrate up    # same as clojure -M:migrate up

# `bb repl` gives a prompt and serves port 7888. `clojure -M:repl` is the
# headless server alone — use it when an editor or the Wagoe MCP server is the
# only client. Either way, eval the dev/user.clj aliases:
(go)    # start the system — http://localhost:3000
(reset) # reload changed namespaces and restart
(halt)  # stop the system

# Testing
clojure -M:test                   # all tests
clojure -M:test --focus-meta :unit        # unit tests only
clojure -M:test --focus-meta :integration # integration tests

# Database
clojure -M:migrate up    # run pending migrations

# Users
bb create-admin          # create the first admin account (interactive)
# A new project has no users. Anything behind :require-role — the admin UI at
# /web/admin/ in particular — redirects to a login you cannot pass until this
# has been run at least once.

# Modules
wagoe add <module>          # add an optional module
wagoe list modules          # human-readable module list
wagoe list modules --json   # machine-readable catalogue (for AI tools)

# Scaffolding — ALWAYS prefer this over hand-writing module code
bb scaffold ai "product module with name, price, stock" --yes   # natural language (needs AI provider)
bb scaffold generate --module-name product --entity Product \
  --field name:string:required --field price:decimal:required   # explicit, no AI needed
bb scaffold integrate product  # write its config key (--dry-run to preview)
bb guide next                  # state-aware: what should happen next?

# AI tooling (needs Ollama or ANTHROPIC_API_KEY / OPENAI_API_KEY)
bb ai explain --file stacktrace.txt   # explain a Clojure/Wagoe error
bb ai gen-tests src/path/to/ns.clj    # generate a test namespace
bb ai sql "find active users with orders in last 7 days"  # HoneySQL from NL
bb setup ai "PostgreSQL with Stripe payments"             # AI-powered config setup

# Diagnostics — start here when something is wrong
wagoe doctor                          # environment + config + commands + setup,
                                      # ending with the one thing to fix
bb check                              # quality gates for code you wrote
                                      # (FC/IS, deps, lint) — a different question
```

`wagoe doctor` is the front door. The individual checks behind it
(`bb doctor:env`, `bb doctor`, `bb smoke-check`, `bb guide next`) still exist
and are what CI calls; reach for one directly only when you already know which.

## Architecture: Functional Core / Imperative Shell

```
src/shop/
├── core/    # Pure functions ONLY — business logic, calculations, transformations
│             # No I/O, no logging, no exceptions, no side effects
└── shell/   # All side effects — HTTP handlers, DB access, external calls, services
```

<!-- gen:fc-is -->
| Direction | Allowed? |
|-----------|----------|
| Shell → Core | ✅ allowed |
| Core → Ports | ✅ allowed |
| Shell → Ports | ✅ allowed |
| Core → Shell | ❌ NEVER — violates FC/IS |
| Core → IO | ❌ NEVER — even logging |

Every module MUST define `ports.clj`.

- core/ may require only pure libraries (clojure.string/set/walk/edn, malli, hiccup, cheshire, buddy.core, honey.sql) and its own core/schema/ports — an allowlist, so anything else is refused by default
- core/ must not throw — return typed error values ({:error {:type ... :message ...}}); the shell translates them into HTTP responses (escape hatch: ^:wagoe/allow-throw ns metadata or .wagoe/check-fcis.edn)
- core/ must not hold mutable state (defonce/atom/swap!/reset!) — definition registries and process state live in the shell (wagoe.<lib>.shell.registry)
- cross-module calls go through service ports
- web/HTTP layers never require *.shell.persistence directly

```clojure
(ns shop.core.product)
(defn calculate-total [items] (reduce + (map :price items)))
```
<!-- /gen:fc-is -->

```clojure
;; ✅ CORRECT — core is pure
(ns shop.core.product)
(defn calculate-total [items] (reduce + (map :price items)))

;; ❌ WRONG — core must never do I/O
(ns shop.core.product
  (:require [shop.shell.persistence :as db]))  ; NEVER
```

**Module structure when adding new functionality:**

```
src/shop/
├── schema.clj               # Malli validation schemas (shared)
├── ports.clj                # Protocol definitions (interfaces)
├── core/
│   └── {domain}.clj         # Pure business logic
└── shell/
    ├── persistence.clj      # Database access
    ├── service.clj          # Business operations (orchestrates core + adapters)
    └── http.clj             # HTTP handlers and routes
```

## Critical Conventions

### Case conversion — a frequent source of bugs

<!-- gen:naming -->
| Location | Convention | Example |
|----------|-----------|---------|
| All Clojure code | kebab | `:password-hash, :created-at` |
| Database boundary only | snake | `password_hash, created_at` |
| API/JSON boundary only | camel | `passwordHash, createdAt` |
<!-- /gen:naming -->

Convert **only at boundaries** — never in business logic:

```clojure
;; At persistence boundary — db record → Clojure entity
(defn db->entity [row]
  (clojure.set/rename-keys row {:created_at  :created-at
                                 :updated_at  :updated-at
                                 :user_id     :user-id}))

;; At persistence boundary — Clojure entity → db params
(defn entity->db [entity]
  (clojure.set/rename-keys entity {:created-at  :created_at
                                    :updated-at  :updated_at
                                    :user-id     :user_id}))
```

### Adding new fields — always synchronise all three

1. Malli schema in `schema.clj`
2. Database column (new migration file)
3. Persistence layer transformations in `shell/persistence.clj`

Missing any one of these causes `nil` values or SQL errors at runtime.

### Exception handling — always include `:type`

```clojure
;; ❌ WRONG — no :type causes generic 500 errors
(throw (ex-info "Not found" {:id user-id}))

;; ✅ CORRECT
(throw (ex-info "User not found"
                {:type    :not-found
                 :id      user-id
                 :message "No user with this ID exists"}))
```

Valid `:type` values: `:validation-error` `:not-found` `:unauthorized` `:forbidden` `:conflict` `:internal-error`

### Parenthesis repair

Never manually fix unbalanced parentheses — use the tool:

```bash
clj-paren-repair src/shop/core/product.clj
```

## Development Workflow

### Adding new functionality

**Step -1 — check existing Wagoe modules FIRST.** Before designing or writing
anything, check whether a Wagoe module already provides the functionality
(auth, storage, jobs, email, cache, search, payments, realtime, workflow, …):

```bash
wagoe list modules          # what exists (see “Wagoe Modules” below)
wagoe list modules --json   # machine-readable, for agents
```

If a module covers the need, `wagoe add <module>` and use its ports — never
reimplement what a module already ships. Only build custom code for genuinely
domain-specific logic. Installed modules and their docs are listed at the bottom
of this file.

**Step 0 — scaffold it.** Never hand-write a new module skeleton:

```bash
bb scaffold ai "invoice module with customer name, total, status" --yes
bb scaffold integrate invoice
```

The scaffolder generates schema, ports, core, shell, tests, and migrations.
Then edit the generated code following this flow:

1. **Define schema** in `schema.clj` (Malli)
2. **Write pure core logic** in `core/{domain}.clj` — no side effects
3. **Write unit tests** for core logic (fast, no mocks needed)
4. **Define protocol** in `ports.clj` if the feature needs an adapter
5. **Implement service** in `shell/service.clj` — orchestrates core + DB + adapters
6. **Add HTTP handler** in `shell/http.clj`

### Testing workflow

```bash
# During development — watch a namespace
clojure -M:test --watch

# Before committing
clojure -M:test
```

Tag tests with metadata:

```clojure
(deftest ^:unit validate-email-test ...)        ; pure core test, no DB
(deftest ^:integration create-user-test ...)    ; service test with mocked adapters
```

## Common Pitfalls

<!-- gen:pitfalls -->
### 1. snake_case vs kebab-case mixing

- **Symptom:** Using snake_case internally causes nil lookups.
- **Cause:** snake_case keys used inside Clojure code instead of converting only at boundaries.
- **Fix:** Always use kebab-case internally; convert at the persistence/HTTP boundary only via snake-case->kebab-case-map / kebab-case->snake-case-map.

### 2. defrecord changes not taking effect

- **Symptom:** (ig-repl/reset) doesn't recreate defrecord instances.
- **Cause:** ig-repl/reset reuses existing defrecord instances rather than recompiling them.
- **Fix:** Run (ig-repl/halt) then (ig-repl/go), or restart the REPL entirely.

```clojure
(ig-repl/halt)
(ig-repl/go)
;; OR restart REPL entirely
```

### 3. validation in wrong layer

- **Symptom:** Validation side effects placed in pure core code.
- **Cause:** Calling valid?/throwing inside core functions instead of in the shell service.
- **Fix:** Validate in the shell; pass clean data into core functions.

```clojure
;; ❌ WRONG - Validation in core
(defn create-user [user-data]
  (when-not (valid? user-data)  ; Side effect in pure code!
    (throw ...)))

;; ✅ CORRECT - Validation in shell
(defn create-user-service [user-data]
  (let [[valid? errors data] (validate user-data)]
    (if valid?
      (user-core/create-user data)  ; Core gets clean data
      (throw ...))))
```

### 4. core depending on shell

- **Symptom:** Core namespace requires a shell namespace.
- **Cause:** Core requiring shell.persistence (or other shell IO) instead of depending on ports only.
- **Fix:** Core depends on ports only; keep core functions pure.

```clojure
(ns shop.core.user
  ;; WRONG - Core requires shell namespace
  (:require [shop.shell.persistence :as db]))  ; BAD!

;; CORRECT - Core depends on ports only
(ns shop.core.user)
(defn find-user-decision [user-id existing-user] ...)  ; Pure logic
```

### 5. exception handling - missing :type in ex-data

- **Symptom:** Exceptions without :type in ex-data trigger generic 500 errors; log warning "Exception reached HTTP boundary without :type in ex-data".
- **Cause:** Throwing exceptions from Java methods or using ex-info without a :type key.
- **Fix:** Wrap external/Java calls in try-catch and ensure ALL ex-info calls include a :type (validation-error, not-found, unauthorized, forbidden, conflict, or internal-error).

```clojure
;; WRONG - No :type in ex-data
(parse-long "invalid")  ; Throws NumberFormatException (no ex-data)
(UUID/fromString "bad") ; Throws IllegalArgumentException (no ex-data)
(throw (ex-info "Error" {:field :foo}))  ; Missing :type

;; CORRECT - Wrap in try-catch with :type
(try
  (parse-long value)
  (catch NumberFormatException _
    (throw (ex-info "Invalid integer value"
                    {:type :validation-error
                     :field field-keyword
                     :value value
                     :message "Must be a valid integer"}))))
```

### 6. module routes — the prefix is added for you

- **Symptom:** A route answers at /api/v1/api/my-resource instead of /api/v1/my-resource, or the module serves nothing at all and says nothing about it.
- **Cause:** A module's :wagoe/<name>-routes component returns a contribution — {:api [..] :web [..] :static [..]} — and the platform prefixes each part before mounting it: :api is versioned under /api/v1, :web mounted under /web. Paths written with the prefix already on them get it twice. A flat vector returned instead of the three-key map contributes zero routes, and nothing errors.
- **Fix:** Write Reitit route data at paths relative to the mount point, and return the three-key map. `bb scaffold generate` writes both; this is what to preserve when editing by hand.

```clojure
;; WRONG — prefix written twice, and a flat vector instead of a contribution
(defn my-routes [svc _config]
  [["/api/my-resource"
    {:get {:handler (fn [req] ...)}}]])

;; CORRECT
(defn api-routes [svc]
  [["/my-resource"          ; no /api — versioning adds /api/v1
    {:get {:handler (fn [req] ...)
           :summary "..."}}]])

(defn my-routes [svc config]
  {:api    (api-routes svc)
   :web    (web-routes svc config)   ; paths without /web
   :static []})
```

### 7. forward references — define before use

- **Symptom:** Unable to resolve symbol: my-helper in this context; Syntax error compiling.
- **Cause:** Private helpers placed after the public functions that call them; Clojure compiles top-to-bottom.
- **Fix:** Private helpers must always appear above the first function that calls them (in src/, dev/, and test/ alike).

```clojure
;; WRONG — system-component is called before it is defined
(defn dev-resend-invite! [...]
  (let [svc (system-component :wagoe/my-service)] ...))  ; used here

(defn- system-component [k]   ; defined here — too late!
  (get integrant.repl.state/system k))

;; CORRECT — helper defined first
(defn- system-component [k]
  (get integrant.repl.state/system k))

(defn dev-resend-invite! [...]
  (let [svc (system-component :wagoe/my-service)] ...))
```
