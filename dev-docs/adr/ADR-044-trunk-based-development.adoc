= ADR-044: Trunk-Based Development
:status: Proposed
:date: 2026-11-20
:deciders: wagoe-team

== Status

Proposed (BOU-1036), for the core team to read and accept before the cut-over
(BOU-1042).

== Context

Every change went through a branch, a pull request and a CI run, and branch
protection required the pull request to be up to date with `main`. The baseline
of 19 November 2026 (BOU-1023) measured what that cost:

* A green run took 8 minutes (p90 11), but a pull request needed a median of
  three runs: every merge made the green build of every other open pull request
  stale, so it was rebased and run again: three runs of about 8 minutes per
  change, more with several people working at once.
* A run cost 71 runner minutes, and 36 of 200 runs were cancelled by a newer
  push.
* Of the last 30 red runs, more than half failed on the environment (10: DNS,
  Maven Central) or a flaky test (6), not on the change.

The team is small and works on many small tickets in parallel, so the
up-to-date rule turned into queueing.

== Considered options

Merge queue::
  GitHub tests each pull request on top of the ones ahead of it. It removes the
  rebasing by hand but not the run per change, and a red entry stalls the queue
  behind it.

Two layers of CI::
  A fast check on the pull request, the full suite later. It shortens each wait
  but keeps the stale-build rebase loop.

Drop the up-to-date rule::
  Pull requests stop going stale. Semantic conflicts between two green pull
  requests then reach `main` untested, and nothing stops the line when they do.

Trunk-based development::
  The core team commits straight to `main` behind a local gate, and CI on
  `main` detects instead of gating.

== Decision

Trunk-based development for the core team; pull requests for external
contributors and for the changes that still want one (breaking, security,
new library or migration, or when the author asks). Two gates:

. *The local check* before a push to `main`. The pre-push hook refuses a commit
  that was not simplified and reviewed (`Simplified-by` and `Reviewed-by`, or
  `Review-skipped: <reason>`; a revert is exempt) and then runs `bb check`: every quality gate, the
  CSS build and the tests of what changed (BOU-1024, BOU-1025, BOU-1041).
. *The tag*. `bb release` tags only a commit CI passed on `main`, and
  `publish.yml` checks that again before anything reaches Clojars
  (BOU-1029, BOU-1030).

CI on a pull request runs a fast layer; CI on `main` runs everything, moves the
`green` tag to each passing commit, and opens a "main is red" issue when it
fails (BOU-1026, BOU-1028).

== Consequences

We gain speed: a change waits for one local check and no rebases, and the
pull requests that remain run on half the runner minutes (71 to 36 per run).

We give up two things:

* *Review before the merge.* Review moves to the author's machine (the
  `review-pr` skill on the local diff, recorded in the commit) and to a daily
  reader of the previous day's commits. A trailer proves the review ran, not
  that it was good.
* *An always-green `main`.* A commit can break what its local check did not
  cover: a library that loads the changed one, MySQL, e2e, the smokes. CI on
  `main` finds it minutes later.

That is acceptable for a framework that ships tagged releases. Users take
versions from Clojars, not commits from `main`, and no tag lands on a red
commit. What `main` gives in between is a short window of red that only the
team sees, against three CI runs of queueing for every change.

== Conditions

The decision holds only while these hold:

* *The local check matches CI* for what it covers. `bb check` is the same
  registry CI's gate job runs; what it leaves out (dependent libraries, MySQL,
  e2e, smokes) is named in the docs.
* *Stop the line.* A red `main` is reverted first and debugged afterwards;
  nobody pushes on top of it but the revert.
* *`main` stays releasable.* Unfinished work lands as `:incubating` or behind
  `^:no-doc`, never as public API (BOU-1033).

We look at it again four weeks after the cut-over, against the baseline
(BOU-1040).
